## Overall Impression

This is a genuinely well-crafted, specifically-authored screen, not an assembled template — both assessments independently converge on that. The single biggest opportunity is that the two real DESIGN.md violations found are **regressions in exactly the two ways this codebase was always going to drift**: a pattern fixed on the map (Unicode glyphs → real SVG shapes) wasn't propagated to the toolbar right next to it, and a pattern rejected on the two screens this session touched (colored left-border tabs) reappeared on the admin console a teammate built separately. ## Priority Issues

**[P0] Unauthenticated public admin console, live, with test debris in its audit trail**
**Why it matters**: The product's entire defense — "근거 없는 숫자는 화면에 올리지 않는다" — depends on the numbers being tamper-evident. `admin.html` is reachable from the main nav drawer on the public deployment right now, boots straight in with "이 서버는 관리자 인증 없이 열려 있습니다," no login, and its own visible change-history log already contains an entry with reason `"aaaaa"`. Anyone — including a judge exploring the nav during the 3-minute evaluation window PRODUCT.md says is make-or-break — can silently change a unit cost or threshold with a free-text reason and no authentication.
**Fix**: Set `ADMIN_TOKEN` on the live deployment before any judged demo, or pull the admin link from the public nav until it's set — `admin.js` already wires auth automatically once the server requires it; this is a config change, not a rebuild.
**Suggested command**: `/impeccable harden`

**[P1] Dark-mode contrast failure on the tab you click most — including the new 평일/주말 toggle**
**Why it matters**: `.pbtn.on{background:var(--brand);color:#fff}` is hardcoded white and never overridden for dark mode. Live-measured: active period/daytype tab text = **2.60:1** (fails AA's 4.5:1, fails even the 3:1 large-text floor); the orange active-tab underline marker on that same blue = **1.14:1** ("near-invisible"). This browser session renders in dark mode by default (matches system preference — not a forced edge case). Because the 평일/주말 toggle added this session reuses `.pbtn`/`.pbtn.on` for its own buttons, it inherited this pre-existing bug immediately. The fix pattern already exists in the same file for the identical blue background — seven other classes (`.btn.primary`, `.plist .ai-tag`, `.simtool.on`, etc.) already get a dark-mode `color:var(--bg)` override; `.pbtn.on` was simply left off that list.
**Fix**: Add `.pbtn.on` to the existing dark-mode override block (`app.css` ~1566-1588) alongside the other `--brand`-background classes; separately reconsider the orange underline marker's color against blue specifically in dark mode.
**Suggested command**: `/impeccable audit`

**[P1] Toolbar/placement-list icons regressed to raw Unicode glyphs**
**Why it matters**: `simulation.js:295` and `:870` render `●`/`◆`/`▲` as text for the three placement tools, while the map and its own legend draw real SVG shapes for the identical three types via `markerShape()` (`map.js:1178`) — with a code comment documenting the team already fixed this exact pattern once for the map. This is the densest decision point in the product (수단 선택 before every placement) and the single most checkable "does this look hand-built" spot in the UI.
**Fix**: Swap the toolbar/list glyph for a call to the same shape renderer already used one file over — the shape logic is already parameterized by type.
**Suggested command**: `/impeccable polish`

**[P1] Colored left-border "sidebar tab" reappeared on the admin console**
**Why it matters**: `admin.css:25-27` (`.admopen`) and `:36-37` (`.admrow.changed`) both use a `border-left:3px` accent — the exact pattern DESIGN.md names by name as "AI가 만든 화면의 대표 표식이라 검출기도 잡습니다." The dashboard/simulation screens explicitly rejected this same pattern for `.brief`, citing the identical rule. It broke on the one screen this session didn't touch.
**Fix**: Replace both with the established alternative already used elsewhere (top-of-card accent, or the `--brand` title-mark pattern DESIGN.md documents).
**Suggested command**: `/impeccable polish`

**[P1] The map's 786 grid cells have zero keyboard access**
**Why it matters**: Confirmed via live DOM query — none of the `.cells rect` elements carry `tabindex`, `role`, or `aria-label`; the enclosing `<svg>` is announced to screen readers as one static image. PRODUCT.md commits to WCAG 2.1.1 keyboard operability and states the team already found and fixed this exact class of bug once, on the region table. The fix pattern is proven in this same codebase; it wasn't extended to the highest-traffic surface in the app. The only current workaround is typing an exact grid ID you'd normally only learn by already having interacted with the map.
**Fix**: Apply the same `tabindex`/`role="button"`/keydown pattern already used on `.rgtbl th[data-sort]` and `tr[data-region]` to the cell layer — or make the Top10/region-table the primary keyboard path and the map the visual confirmation surface (see Questions below).
**Suggested command**: `/impeccable adapt`

**[P2] No unsaved-work guard on the simulation page**
**Why it matters**: Only `admin.js` registers a `beforeunload` handler; `simulation.js` holds an unsaved placement plan with the identical "gone if you leave" risk `admin.js` explicitly protects against for parameter edits. The realistic failure mode: a 공무원 mid-plan clicks "대시보드" to sanity-check a number and the plan silently vanishes — worst case, minutes before the meeting the whole product exists to prep for.
**Fix**: Port the same three-line guard from `admin.js`, gated on `S.placements.length > 0`.
**Suggested command**: `/impeccable harden`

## Persona Red Flags

**Alex (impatient power user, desktop)**
- Cannot keyboard-navigate the map grid at all — the single most-repeated action in the app requires the mouse every time; no accelerator keys for period-tab switching either.
- The armed-tool indicator pill can scroll out of view once the AI-recommend box grows the sidebar — Alex loses the "what's armed" signal exactly when moving fast.
- Positive: `guardFor()` blocks a bad click instantly with a specific reason instead of a silent no-op — genuinely reduces the trial-and-error Alex hates.

**Sam (accessibility-dependent, keyboard/screen-reader)**
- Cannot operate the map at all — 0/786 cells focusable, announced as a single static image. Both the dashboard's "click the red cell" loop and the simulation's placement loop are closed to Sam except via exact-ID search.
- Same gap on the scatter plot and hourly-profile chart — mouse-only listeners, no keyboard equivalent.
- Positive: `role="tablist"`/`aria-selected`, `aria-pressed`, a real visible focus-visible outline in brand color, and the region table's proven keyboard-fix pattern show the team knows exactly how to do this right — it just wasn't generalized to the map.

**"교통 담당 공무원, 회의 5분 전" (project-specific)**
- Strength: the one-line auto-briefing at the top of the dashboard gives an instantly quotable sentence for walking into a meeting.
- Strength: the 정책 판단 요약 card hands a ready phrase plus a defensible number chain under time pressure.
- Risk: exactly the P2 above — a "double-check a number mid-prep" action can silently destroy an unsaved plan.
- Risk: AI report generation takes several seconds against live infra with a 2-minute timeout budget, but shows one static spinner line with no step/percentage indicator — a real anxiety point under this persona's stated time pressure, not hypothetical.
