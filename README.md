# 화성시 버스 수요·공급 미스매칭 대시보드

교통카드 실현수요와 거주인구 기반 잠재수요를 같은 격자에서 대조해
**대중교통 사각지대**를 찾아내고, **노선 조정 우선순위**와 **정책 시뮬레이션**을
한 화면에서 제공하는 웹 대시보드입니다.

화성시 AI 공모전 출품작 · 프론트엔드. 모든 수치는 백엔드
([hwaseong-dashboard-backend](https://github.com/2026-AIHwaseong-project/hwaseong-dashboard-backend))가
공공데이터로 산출한 **실데이터**입니다.

---

## 바로 실행

백엔드 서버가 데이터를 공급합니다. 백엔드를 먼저 켜세요.

```bash
# 1) 백엔드 기동 (백엔드 리포에서)
python main.py            # → http://localhost:8000

# 2) 화면 열기 — 셋 중 하나
#    a. 백엔드가 프론트를 직접 서빙합니다 (두 리포가 같은 폴더에 있을 때)
http://localhost:8000/app/

#    b. 개발 서버로 열기 (프론트 리포에서)
python3 tools/dev-server.py 5500     # → http://localhost:5500/

#    c. index.html 을 브라우저로 직접 열기 (file:// — localhost:8000 을 자동으로 찾음)
```

다른 PC·터널(ngrok)의 백엔드로 붙일 때는 코드를 고치지 말고 주소 뒤에 `?server=` 를 붙이세요.

```
index.html?server=https://xxxx.ngrok-free.app   # 한 번 열면 브라우저에 기억됩니다
index.html?server=                              # 기억된 주소 초기화
```

빌드 도구·외부 라이브러리는 없습니다. `npm install` 이 필요 없습니다.

## 팀 역할별 안내

### 🎨 프론트엔드 · 디자인 담당

**`assets/css/app.css` 만 보면 됩니다.**

- 파일 맨 위 `:root` 에 모든 색·그림자가 CSS 변수로 정의돼 있습니다.
  변수 값만 바꾸면 두 화면 전체 톤이 한 번에 바뀝니다.
- 라이트/다크 각각 별도로 정의돼 있습니다(자동 반전이 아니라 각각 조정한 값).
  상단 [테마] 버튼으로 `자동 → 라이트 → 다크` 순환 확인 가능.
- 컴포넌트는 번호 매긴 구획으로 나뉘어 있고 목차가 파일 상단에 있습니다.

시각화 색 규칙(지키면 색각 이상·흑백 인쇄에서도 읽힙니다):

| 용도 | 규칙 | 변수 |
|---|---|---|
| 미스매칭 MI | 발산형 — 파랑 ← **무채색** → 빨강 | `--mi0` ~ `--mi6` |
| 수요·유동인구 | 순차형 단일 색상(파랑) | `--sb0` ~ `--sb4` |
| 공급 | 순차형 단일 색상(주황) | `--so0` ~ `--so4` |
| 승차/하차 | 범주형 2색 — 파랑·주황 | `--c-board` / `--c-alight` |
| 전/후 비교 | **색이 아니라 스타일로 구분** (기준선=점선 고스트, 시나리오=채움) | `--ink3` / `--c-board` |
| 좋음/나쁨 | 반드시 부호·라벨과 함께 | `--good` / `--bad` |

### 🔌 백엔드 담당

**연동은 완료 상태입니다.** 규격은 `docs/API.md`, 응답 스키마의 기준은 백엔드 실서버입니다.
서버가 아직 안 주는 파생 필드는 `assets/js/api.js` 의 어댑터가 "빠진 키만" 보충합니다 —
서버가 채워 보내기 시작하면 어댑터는 자동으로 물러납니다.

AI 보고서 생성(Claude API)은 **반드시 백엔드에서** 호출합니다.
프론트엔드에 API 키를 두면 브라우저에서 그대로 노출됩니다.
호출 규격은 `docs/AI-REPORT.md` 참고.

## 산출 로직 (백엔드 산출 · 화면은 표시만)

```
D  수요지수   = 0.5·정규화(교통카드 승하차) + 0.5·정규화(연령가중 유동인구)
S  공급지수   = 0.78·정규화(운행빈도) + 0.22·정류장 커버리지 + 배치효과
MI 미스매칭   = z(D) − z(S)   ← 양수가 클수록 공급 부족
우선순위      = MI⁺ × 수요규모 × (1 + 1.6·고령인구비)
추천 배치안   = 총사업비 1원당 미해결 통행 감소량이 큰 순 (예산 제약 하 탐욕적 선택)
잠재수요      = SGIS 격자 거주인구 × 통행 원단위 0.25 (가정계수)
```

### 최적화는 알고리즘, 설명은 AI

**추천 배치 위치는 언어모델이 아니라 최적화 알고리즘이 정합니다.**
LLM 에 맡기면 매번 답이 달라지고 근거를 댈 수 없습니다.
AI 는 선정 근거를 문장으로 다듬는 일만 맡습니다.

> 심사에서 "AI가 어떻게 위치를 정했나요?" 라고 물으면
> **"예산 제약 하 한계효과 최대화 알고리즘으로 선정하고, 선정 근거를 AI가 문서화합니다"**
> 라고 답하시면 됩니다.

수단별 진단 규칙도 서로 겹치지 않게 정해 두었습니다. 이 구분이 없으면
가장 싼 정류장이 아무 데나 선택됩니다.
(커버리지 = 1 − 최근접 정류장 거리/600m)

| 정류장 커버리지 | 진단 | 수단 |
|---|---|---|
| ≥ 0.5 (약 300m 이내) | 정류장은 도보권 안, 버스가 뜸함 | 배차 증편 |
| 0.15 ~ 0.5 (약 300~510m) | 노선은 인근인데 정류장이 멀다 | 정류장 신설 |
| < 0.15 (510m 초과) | 노선망 자체가 닿지 않음 | 똑버스(DRT) |

**비용 단위 주의** — 정류장 4,200만 원은 1회성 시설비이고 똑버스 1.8억 원은
연간 운영비입니다. 단가는 아직 **가정값**이라(실제 사업비 미확정) 화면·보고서에
"가정값" 표시가 자동으로 붙습니다.

설계상 짚어 둘 점 두 가지:

- **실현수요는 공급에 눌립니다.** 버스가 없어서 발생하지 못한 통행이 있으므로,
  교통카드 승하차만 보면 사각지대를 과소평가하게 됩니다. 그래서 유동인구
  기반 잠재수요를 절반의 가중치로 함께 봅니다.
- **정규화 기준은 배치 없는 상태에서 한 번만 잡고 고정합니다.** 매번 다시 잡으면
  시뮬레이션 전후 KPI를 서로 다른 자로 재는 셈이 되어 비교가 무의미해집니다.

엑셀 보고서의 "산출식·주석" 시트에 항목별로 표기됩니다.
대표적으로 **시간대별 승하차는 추정**입니다(원자료가 일자별 집계라 시간대 정보가 없어
유동인구 연령가중 시간배율로 안분). 화면에도 "추정치" 배지가 붙습니다.

## 행정경계 데이터

지도의 읍면동 경계는 SGIS 원본 SHP 에서 만들어 씁니다.
`assets/data/boundary.js` 는 자동 생성 파일이므로 직접 고치지 마세요.

```bash
# SGIS > 자료제공 > 경계 > 읍면동 에서 받은 SHP 세트를 프로젝트 루트에 두고
pip install pyshp pyproj
python3 tools/build-boundary.py
```

원본 SHP(135MB)는 `.gitignore` 처리했습니다. 좌표점을 63,204개에서 5,759개로
줄여(약 25m 허용오차) 122KB 로 만들었고, EPSG:5179 → EPSG:4326 변환을 거칩니다.

## 개발용 서버

`python3 -m http.server` 는 캐시 헤더를 보내지 않아, 코드를 고쳐도 브라우저가
예전 `.js` 를 계속 쓰는 일이 생깁니다. 대신 이걸 쓰세요.

```bash
python3 tools/dev-server.py 5500
```

응답마다 `Cache-Control: no-store` 를 붙여 항상 최신 파일을 받아갑니다.

## 데이터 주의사항

지도의 행정경계·격자·노선·정류장·승하차는 공공데이터 기반 **실데이터**입니다.
다만 다음은 실측이 아닙니다 — 화면에도 같은 표기가 붙습니다.

- **시간대별 승하차**: 일자별 실측 총량을 유동인구 시간배율로 안분한 **추정치**
- **잠재수요**: 거주인구 × 통행 원단위 0.25 (**가정계수**)
- **사업비 단가·내용연수**: 실제 사업비 미확정 (**가정값**)

시뮬레이션·추천 결과는 위 가정에 기반한 정책 검토용 참고 수치이며,
실제 집행 전에는 실측 단가·현장 실사로 재검증이 필요합니다.
