# 화성시 버스 수요·공급 미스매칭 대시보드

교통카드 실현수요와 통신 유동인구 잠재수요를 같은 격자에서 대조해
**대중교통 사각지대**를 찾아내고, **노선 조정 우선순위**와 **정책 시뮬레이션**을
한 화면에서 제공하는 웹 대시보드입니다.

화성시 AI 공모전 출품작 · 프론트엔드

---

## 바로 실행

빌드 도구가 필요 없습니다. 파일을 열기만 하면 됩니다.

```bash
# 방법 1 — 단일 파일 (가장 간편. 파일 하나만 더블클릭)
dist/hwaseong-dashboard.html

# 방법 2 — 원본 그대로 열기
index.html 을 브라우저로 열기

# 방법 3 — 로컬 서버 (백엔드 연동 시 필수)
python3 -m http.server 5500
# → http://localhost:5500/
```

기본값은 **목(mock) 모드**라 백엔드 없이도 전 기능이 동작합니다.

### 단일 파일 버전

CSS·JS를 HTML 안에 전부 넣은 배포용 파일입니다. 인터넷도 서버도 필요 없어
메신저·메일로 보내거나 USB로 옮겨도 그대로 열립니다. 시연·공유용으로 쓰세요.

```bash
node tools/build-standalone.js     # 원본 수정 후 다시 빌드
```

| 파일 | 용도 |
|---|---|
| `dist/hwaseong-dashboard.html` | 분석 대시보드 (약 165KB) |
| `dist/hwaseong-simulation.html` | 정책 시뮬레이션 (약 176KB) |

> 두 파일은 서로를 링크하므로 **같은 폴더에 함께** 두세요.
> 단일 파일 버전은 목 데이터 전용입니다. 실서버 연동은 원본(`index.html` + `assets/`)을 씁니다.

## 팀 역할별 안내

### 🎨 프론트엔드 · 디자인 담당

**`assets/css/app.css` 만 보면 됩니다.**

- 파일 맨 위 `:root` 에 모든 색·그림자가 CSS 변수로 정의돼 있습니다.
  변수 값만 바꾸면 두 화면 전체 톤이 한 번에 바뀝니다.
- 라이트/다크 각각 별도로 정의돼 있습니다(자동 반전이 아니라 각각 조정한 값).
  상단 [테마] 버튼으로 `자동 → 라이트 → 다크` 순환 확인 가능.
- 컴포넌트는 12개 구획으로 나뉘어 있고 목차가 파일 상단에 있습니다.

시각화 색 규칙(지키면 색각 이상·흑백 인쇄에서도 읽힙니다):

| 용도 | 규칙 | 변수 |
|---|---|---|
| 미스매칭 MI | 발산형 — 파랑 ← **무채색** → 빨강 | `--mi0` ~ `--mi6` |
| 수요·유동인구 | 순차형 단일 색상(파랑) | `--sb0` ~ `--sb4` |
| 공급 | 순차형 단일 색상(주황) | `--so0` ~ `--so4` |
| 승차/하차 | 범주형 2색 — 파랑·주황 | `--c-board` / `--c-alight` |
| 전/후 비교 | **색이 아니라 스타일로 구분** (기준선=점선 고스트, 시나리오=채움) | `--ink3` / `--c-board` |
| 좋음/나쁨 | 반드시 부호·라벨과 함께 | `--good` / `--bad` |

### 🔌 백엔드 담당

**`docs/API.md` 한 장이면 됩니다.**

1. 엔드포인트 9개 구현
2. `assets/js/config.js` 에서 `BASE_URL` 설정, `USE_MOCK: false`
3. 끝

응답 형태가 헷갈리면 브라우저 콘솔에서 목 응답을 직접 확인하세요.

```js
HW.mock.handle('grid.list', { period: 'am' })
HW.mock.handle('simulations.run', null, { placements: [{type:'stop', cellId:'G-453', count:1}] })
```

**하나만 먼저 붙여 보기** — 격자 API만 실서버로:

```js
ENDPOINT_OVERRIDES: { 'grid.list': false }
```

AI 보고서 생성(Claude API)은 **반드시 백엔드에서** 호출하세요.
프론트엔드에 API 키를 두면 브라우저에서 그대로 노출됩니다.
호출 규격은 `docs/AI-REPORT.md` 에 실행 가능한 코드로 정리돼 있습니다.

## 산출 로직

```
D  수요지수   = 0.5·정규화(교통카드 실현 승하차) + 0.5·정규화(통신 유동인구)
S  공급지수   = 0.78·정규화(운행빈도) + 0.22·정류장 커버리지 + 배치효과
MI 미스매칭   = z(D) − z(S)   ← 양수가 클수록 공급 부족
우선순위      = MI⁺ × 수요규모 × (1 + 1.6·고령인구비)
```

설계상 짚어 둘 점 두 가지:

- **실현수요는 공급에 눌립니다.** 버스가 없어서 발생하지 못한 통행이 있으므로,
  교통카드 승하차만 보면 사각지대를 과소평가하게 됩니다. 그래서 통신 유동인구
  기반 잠재수요를 절반의 가중치로 함께 봅니다.
- **정규화 기준은 배치 없는 상태에서 한 번만 잡고 고정합니다.** 매번 다시 잡으면
  시뮬레이션 전후 KPI를 서로 다른 자로 재는 셈이 되어 비교가 무의미해집니다.

## 면책

현재 화면의 지도 경계·격자·노선·정류장과 모든 수치는 로직 시연을 위한
**가상 예시 데이터**입니다. 실제 지리·운행 정보와 다르며 정책 판단의 근거로
사용할 수 없습니다. 실데이터 전환 후에는 `config.js` 의 `APP.isMockData` 를
`false` 로 바꾸면 화면의 목업 배지와 면책 문구가 사라집니다.
